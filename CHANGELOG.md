## [v8.0.73] - 2026-11-09

### Fixed
- **快照回填无分隔符窗口名下 Argon 误折叠进 Gemini 修复 (`internal/console/api/quota_parse.go`, `api/quota_parse_unit_test.go`)**:
  - 根因：`hydrateQuotaGroupsFromSnapshots` 在快照缺少 `:` 或 ` - ` 分隔符时（如 Google 原生窗口名 `gemini-argon-wtu-weekly`），`grpName` 默认为空，回退分支先执行 `strings.Contains(wLower, "gemini")`，导致 Argon 再次被折叠进 `models/gemini`，引发 0% 额度覆盖。
  - 修复：回退分组推断中优先判定 `argon` / `gemini 4`，与主规范化逻辑对齐。新增 `TestHydrateKeepsArgonSeparateFromGeminiWithoutDelimiters` 单测保证隔离。
- **管理层 API `/v0/management/api-call` 缺失非 Claude 3P 模型冷却回退 (`internal/api/handlers/management/api_tools_tokens.go`, `api_tools_test.go`)**:
  - 根因：`reconcileAntigravityQuotaResponse` 仅将包含 claude/gpt 等关键词的模型归入 3P 冷却，缺少控制台具备的 `else` 回退分支，导致 Antigravity 在 DeepSeek/Llama/Qwen 等 3P 模型触发 429 冷却时，管理页与控制台状态严重脱节（管理页仍显示 100% 可用）。
  - 修复：补全 `else` 分支将所有非 Gemini 非 Argon 模型的冷却统一注入 3P 配额池。新增 `TestReconcileAntigravityQuotaResponse/ThirdPartyModelCooldown45h_OverridesClaudeGroupToZero` 单测覆盖。
- **窗口规范化贪婪匹配修正与月度限额支持 (`internal/console/db/queries_upstream.go`, `api/quota_parse.go`, `db/queries_upstream_dedup_test.go`)**:
  - 根因：`canonicalQuotaWindow` 与 `is5h` 包含宽泛的 `strings.Contains(w, "hour")`，导致任意含有 hour 的窗口（如 `1 hour`、`hourly`）被错误识别为 `5h`（5小时周期）。
  - 修复：精化为精确匹配 `5h`/`5 hour`/`five hour` 系列词组，补充 `monthly` 规范化映射。更新 `TestNormalizeQuotaWindowKey` 单测。
- **数据库快照反查去重组名规范化 (`internal/console/db/queries_upstream.go`, `db/queries_upstream_dedup_test.go`)**:
  - 根因：`normalizeQuotaWindowKey` 仅规范化窗口后缀而保留原始组名，导致历史行 `Gemini Models:5h` 与 `models/gemini:5h` 产生不同去重 key，无法在 SQL 阶段合并。
  - 修复：新增 `canonicalQuotaGroup` 将旧组名映射至权威标识，实现 SQL 去重键精确合并。
- **Codex Team/Enterprise 28天/30天月度限额识别与前端适配 (`internal/console/api/quota_parse.go`, `assets/console-quotas-render.js`, `assets/console-i18n.js`, `assets/console.html`, `api/quota_parse_unit_test.go`)**:
  - 根因：Codex Team 账号中 `secondary_window` 为月度限额（`limit_window_seconds >= 2419200`），后端硬编码为 `codex-weekly`（周限额），导致前端显示"周限额 剩余 100% (28 天 11 小时)"的严重认知歧义。
  - 修复：后端动态识别月度限额并下发 `codex-monthly` / `monthly` 标识；前端紧凑卡片自适应呈现"月"度标签与月度说明。
  - 资源引用全链路缓存击穿升级：`console.html` 37 处静态资源版本号全量自增刷新至 `?v=v8.0.73`。

## [v8.0.72] - 2026-11-09

### Fixed
- **Console 额度卡周限额误判为 0%（"上游已禁用/周限额耗尽"）而管理页显示 99% (`internal/console/api/quota_parse.go`, `api/quota_parse_unit_test.go`, `api/handlers_quotas_test.go`)**:
  - 根因：`normalizeUsedPercent` 未信任字段名自带的单位，改按数值大小猜测量纲——`used > 1.0` 才当作 0~100 的百分数，否则当作 0~1 的小数。Codex 上游 `rate_limit.secondary_window.used_percent` 真实返回 `1`（即已用 1%），被猜成 `1.0` 小数 → 100% 已用 → 剩余 0% → `Disabled: true`，于是同一账号在 Console 显示"周 剩余 0%（上游已禁用/周限额耗尽）"，而 management 页显示"周限额 99%"。
  - 生产实测原始载荷：`primary_window.used_percent: 9`（5h，剩 93%）、`secondary_window.used_percent: 1`（周，剩 99%）；`/v0/management/auth-files` 的 `signals` 亦带 `X-Codex-Secondary-Used-Percent: "1"` 可交叉印证。5 家上游 91 个 `*_used_percent` / `*_remaining_percent` 观测值全为整数百分比。
  - 修复：字段名即单位。`*_percent` 恒按 0~100 解释并换算剩余量（`100 - used`），`*_fraction` 恒按 0~1 解释并先钳制到 `[0,1]` 再换算，删除按量级猜测的分支。这正是 AGENTS.md「单位由字段名声明」的确定性要求：同一份上游载荷不允许有两种解释。
  - 新增 `TestNormalizeUsedPercentUnitDoesNotGuess`（`0→100 / 1→99 / 7→93 / 9→91 / 50→50 / 99→1 / 100→0`）、`TestNormalizeUsedFractionStaysFractional`（`0→100 / 0.01→99 / 0.5→50 / 1→0`）与 `TestParseCodexQuotaGroupsUsesRealUpstreamShape`（喂入生产原样载荷 `primary 9` / `secondary 1`，断言 5h=91%、周=99%）。三个用例在旧实现上分别以 `codex-weekly remaining = 0%, want 99%` 失败。
  - `TestParseCodexQuotaGroups` 既有夹具 `used_percent: 0.35 / 0.8` 同步改为 `35 / 80` 及其期望值 65 / 20，与新语义一致，未放宽断言。
- **Antigravity Gemini 4 Argon 额度被误当作 Gemini 组，导致正常 Gemini 额度显示为 0% (`internal/console/api/quota_parse.go`, `api/quota_parse_unit_test.go`)**:
  - 根因：`hydrateQuotaGroupsFromSnapshots` 用 `strings.Contains(gLower, "gemini")` 判定分组，而 "Gemini 4 Argon" 同样命中该子串，被归一成 `models/gemini`。Argon 与 Gemini 是独立额度池，归一后二者共用 `canonical|window` 去重键，`ORDER BY ts DESC` 下谁先出现谁保留——Argon 周限额耗尽（0%）时，真实的 Gemini 周额度（生产实测 88% / 31%）被顶掉，控制台把 Argon 的 0% 当作 Gemini 池的剩余额度展示。
  - 修复：在普通 Gemini 判定之前先识别 Argon（`argon` / `gemini 4` / `gemini-4` / `gemini4`），归一到独立组 `models/gemini4_argon` / 显示名 "Gemini 4 Argon"，与前端 `console-quotas-render.js` 既有的 Argon 专属徽章渲染保持一致。
  - 新增 `TestHydrateKeepsArgonSeparateFromGemini`，以生产快照行（`Gemini Models:weekly=88`、`Gemini 4 Argon:weekly=0`）分别按「Gemini 先行」「Argon 先行」两种顺序各跑一次；在 HEAD 原实现下 `argon_first` 子用例以 `models/gemini weekly = 0, want 88` 失败，正是线上症状。
- **仓库 3 处 Go 源码 CRLF 行尾归一 (`internal/console/api/router.go`, `api/handlers_traffic_test.go`, `traffichub/hub.go`)**:
  - 按 AGENTS.md「纯 LF」要求将这三处既有 CRLF 转为 LF；内容零改动（`git diff -w` 为空，blob 与工作树逐字节一致）。

## [v8.0.71] - 2026-11-08

### Fixed
- **历史时间尺度（今日/7天等）渠道数据对齐与凭证映射修复 (`internal/console/db/queries_events.go`, `db/models.go`, `traffichub/historical.go`, `api/handlers_traffic.go`)**:
  - 根因：`request_events` 与 `usage_outbox` 中仅记录 16 位 Hex 凭证散列 (`auth_index`)，聚合时 `traffichub.InferChannel` 将 Hex 判定为非渠道代号并退化为按模型名称正则匹配，导致通过 Antigravity、WorkBuddy-CN、Qoder-CN 调用的模型在切换至历史区间（如"今日"）时渠道信息丢失或误判为原生模型。
  - 修复：在 SQLite 聚合查询中执行 `LEFT JOIN upstream_auth_baselines b ON r.auth_index = b.auth_index` 提取权威渠道字段 `b.provider AS channel`，并贯通至 `BuildHistoricalSnapshot` 与 `recentRecords`，确保实时 5m 与历史时间尺度的凭证、模型、渠道归属 100% 严格一致。
- **历史尺度切换耗时从 7.5 秒降至 19 毫秒（解决切换顿卡卡死）(`internal/console/api/handlers_traffic.go`, `db/queries_events.go`)**:
  - 根因：此前 `HandleGetTraffic` 每次收到请求时同步调用 `eng.Flusher().FlushUsage(ctx)`，在并发请求下触发独占写锁竞争与阻塞，导致前台切换时间时冻结 7~8 秒。
  - 修复：移除句柄层的阻塞式 Flush，改在 SQLite 聚合中通过 `UNION ALL` 一次性无锁并行扫描 `request_events` 与 `usage_outbox`，借助 SQLite WAL 机制实现毫秒级（19ms）非阻塞聚合，彻底根除切换顿卡。
- **可视化拓扑图 Qoder / Qoder-CN 官方品牌图标补全 (`internal/console/assets/console-traffic.js`)**:
  - 从 Magpie 权威图形资产 (`magpie/internal/gui/assets/icons/qoder.svg`) 提取 24x24 矢量路径嵌入 `BRAND_ICON_PATHS.qoder` 与 `qoder-cn`，统一绑定 `#ff6a00` 品牌橙色与半透明胶囊底色；并在 `getBrandNodeVisual` 的请求模型与路由渠道分支中补齐对齐映射。
- **全面引入 ui-design Rule 9 骨架屏加载标准 (`internal/console/assets/console-traffic.js`, `console.html`)**:
  - 拓扑时间尺度即时视觉反馈：在 `switchTrafficRange` 触发点击瞬间同步调用增强版 `renderTrafficSkeleton()`，将拓扑画布、顶部 4 张关键指标卡以及底部 IP/地域账本原地替换为 1:1 几何尺寸的微光骨架（`.traffic-skeleton-shimmer`），数据返回后带 `traffic-fade-in` 平滑淡入，彻底消除用户点击后无反馈的停滞感。
  - 控制台全局淘汰"正在加载..."纯文本：将 `keys-tbody`（密钥配置）、`upstream-stats-cards-container`（上游凭证用量卡片）、`antigravity-accounts-tbody`、`validations-history-tbody`、`prices-tbody` 与 `openrouter-accounts-tbody` 原有居中弱文本占位全面升级为与真实卡片/表格对齐的 `.ui-skeleton-row` 与 `.ui-skeleton-card-pad`，实现全控制台各工作区异步加载体验一致性。
